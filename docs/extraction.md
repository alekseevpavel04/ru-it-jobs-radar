**Эталон: предразметка LLM и ручная проверка.** LLM размечает записи по инструкции [`docs/annotation_guide.md`](annotation_guide.md) в два независимых прохода, ни один не видит другого. Где проходы разошлись, третий проход разбирает расхождение и выбирает ответ. Согласие в таблице выше это совпадение двух проходов одной модели по одной инструкции. Оно показывает согласованность предразметки, а не её правильность, и с согласием двух людей не сравнимо. Правильность я проверил сам: прочитал все записи эталона, сверяя текст с разметкой по инструкции, правок не понадобилось ([`limitations.md`](limitations.md)).

## Как считался тест

Тест открывался один раз, одной командой `python -m radar.eval.final --final-test` для всех систем. Каждая система сначала пишет предсказания на test и test Telegram в свой файл, метрики и парные разности считаются, когда готовы все файлы. Прогон шёл с остановками (пауза GPU под другие задачи, зависший шаг AWQ, занятый порт учителя), и после каждой остановки та же команда продолжала с систем, у которых предсказаний ещё нет. Предсказания AWQ со схемой сделаны повторно запуском с `--only` после зависания, до подсчёта метрик. Qwen3-4B без дообучения исключён флагом `--skip` тоже до подсчёта метрик. Метрики посчитаны один раз, по готовым предсказаниям. Каждый запуск, пропуск и подсчёт дописан строкой в [`results/test_runs.log`](../results/test_runs.log) с временем, системой, коммитом и командой.

У всех строк лога и у файлов `results/` коммит помечен `-dirty`. Пометка ставилась по любому изменению в `git status`, включая неотслеживаемые файлы: во время прогона в рабочем дереве лежали незакоммиченные правки параллельной работы и сам `results/test_runs.log`, который появляется с первым запуском. Между перезапусками менялся и код запуска (флаги `--skip` и `--only`, порт учителя), поэтому в логе несколько разных коммитов. Хэши эталона, предсказаний, весов и промпта записаны в [`results/extract/final_test.json`](../results/extract/final_test.json).

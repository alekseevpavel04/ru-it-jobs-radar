# Ограничения и что не сработало

Где выводы проекта кончаются и какие попытки не дали результата. Проблемы с данными вынесены в [data_problems.md](data_problems.md). Коротко в [README](../README.md).

## Ограничения

- Это срез рынка без hh.ru, крупнейшей площадки: открытого API для такой задачи у неё нет. Источники считаются отдельно и не складываются.
- История закрытий и время жизни есть только у снимков портала. Хабр и API портала собираются с <!--n:collect/habr.json:days.0.dt:s-->2026-10-08<!--/n-->, их ряды короткие.
- В Telegram считаются посты, а не вакансии. Посты со списком из нескольких вакансий не входят, и их доля за эти годы выросла. Повтор поста через неделю и позже считается заново. Посты, которые каналы удалили, не видны. Уровень доли навыка зависит от набора каналов, изменение считается внутри каналов.
- Ежедневное обновление извлекает посты квантованной Q4_K_M, история извлечена AWQ-версией той же модели; разница измерена ([autopilot.md](autopilot.md)).
- Telegram-выборки эталона маленькие (dev <!--n:extract/tg_dev_regex.json:n_examples:d-->54<!--/n-->, test <!--n:extract/tg_test_regex.json:n_examples:d-->130<!--/n--> постов), интервалы на них широкие.
- Эталон предразмечен LLM. Согласие двух проходов мерит согласованность модели с самой собой. Сначала я прочитал случайную выборку из <!--n:gold/human_check.json:metrics.records_judged.denominator:d-->50<!--/n--> записей теста, видя разметку (значит, с эффектом якоря), и согласился с ней в <!--n:gold/human_check.json:metrics.verdict_agree.n:d-->50<!--/n--> из <!--n:gold/human_check.json:metrics.verdict_agree.denominator:d-->50<!--/n-->; поштучно по полям отмечены <!--n:gold/human_check.json:metrics.records_checked.n:d-->3<!--/n--> записи, так что долю верных полей эта проверка не даёт (`results/gold/human_check.json`).
- Потом я вручную проверил весь эталон: test <!--n:gold/full_review.json:metrics.test.records_changed.denominator:d-->440<!--/n-->, dev <!--n:gold/full_review.json:metrics.dev.records_changed.denominator:d-->165<!--/n-->, Telegram test <!--n:gold/full_review.json:metrics.tg_test.records_changed.denominator:d-->130<!--/n--> и Telegram dev <!--n:gold/full_review.json:metrics.tg_dev.records_changed.denominator:d-->54<!--/n--> записей, сверяя текст с разметкой по инструкции. Исправлять не пришлось ни одной записи, поэтому метрики на исправленном эталоне те же (`results/gold/full_review.json`, `python -m radar.eval.gold_review`).
- Словарь навыков видел названия навыков из эталона (<!--n:skills/normalization.json:metrics.dictionary_gold_only.n:d-->442<!--/n--> из <!--n:skills/normalization.json:metrics.dictionary_gold_only.denominator:d-->978<!--/n--> записей словаря), поэтому F1 по навыкам оптимистичен. Нормализация одна для всех систем, на сравнение это не влияет.
- Промпт учителей подбирался на Qwen3-8B, YandexGPT-5-Lite работал на том же промпте без настройки.
- Модели зарплаты и навыков построены почти целиком на вакансиях портала. Резюме в подборе синтетические, релевантность задана правилом, а не людьми.
- Оценки дедупа и детектора подозрительных вакансий держатся на маленьких выборках.
- У большинства файлов `results/` в поле `commit` стоит пометка `-dirty`: числа посчитаны на рабочем дереве с незакоммиченными правками или неотслеживаемыми файлами. Пометка ставилась по любому изменению в `git status`; с 2026-10-14 только по изменениям в коде, конфигах, SQL и размеченных данных.

## Что не сработало

- **DPO не поместился в 8 ГБ.** Пары «верный и испорченный ответ» собраны (<!--n:dpo/pairs.json:metrics.pairs_train.value:d-->716<!--/n--> для обучения), но обучение не уложилось в память карты ни в одной из четырёх проб: DPO грузит модель без оптимизаций, на которых шло SFT. Финальная модель обучена только SFT, код DPO и пары остались в репозитории.
- **Детектор подозрительных вакансий: отрицательный результат.** Слабые метки от правил, классификатор поверх них, проверка на <!--n:models/suspicious.json:scores_dev.labeled:d-->150<!--/n--> карточках dev и <!--n:models/suspicious.json:scores_test.labeled:d-->150<!--/n--> карточках test с предразметкой LLM и ручной проверкой. На dev F1 <!--n:models/suspicious.json:scores_dev.systems.classifier.f1.value:.3f-->0.135<!--/n--> [<!--n:models/suspicious.json:scores_dev.systems.classifier.f1.ci_low:.3f-->0.042<!--/n-->; <!--n:models/suspicious.json:scores_dev.systems.classifier.f1.ci_high:.3f-->0.674<!--/n-->], верных <!--n:models/suspicious.json:scores_dev.systems.classifier.sample_tp:d-->13<!--/n--> из <!--n:models/suspicious.json:scores_dev.systems.classifier.sample_flagged:d-->23<!--/n--> отмеченных. На test F1 <!--n:models/suspicious.json:scores_test.systems.classifier.f1.value:.3f-->0.428<!--/n--> [<!--n:models/suspicious.json:scores_test.systems.classifier.f1.ci_low:.3f-->0.192<!--/n-->; <!--n:models/suspicious.json:scores_test.systems.classifier.f1.ci_high:.3f-->0.919<!--/n-->], верных <!--n:models/suspicious.json:scores_test.systems.classifier.sample_tp:d-->17<!--/n--> из <!--n:models/suspicious.json:scores_test.systems.classifier.sample_flagged:d-->33<!--/n--> отмеченных: интервал такой ширины почти ничего не говорит. Две итерации новых признаков на dev F1 не подняли. Из подозрительных карточек dev формальные вакансии <!--n:models/suspicious.json:scores_dev.categories.formal:d-->21<!--/n--> из <!--n:models/suspicious.json:scores_dev.suspicious:d-->23<!--/n-->, а их по одной карточке не отличить от обычной ([`docs/suspicious_guide.md`](suspicious_guide.md)).
- **Прогноз спроса.** Бустинг по лагам не обошёл скользящее среднее за 4 недели, ETS обошёл его ненамного ([models.md](models.md)). Прогноз, который почти не отличается от текущего уровня, на сайте ничего не добавлял, и его убрали. По той же причине убран недельный дайджест: за неделю доля навыка сдвигается примерно на свой случайный разброс. Сценарий n8n, который его собирает, остался в локальном стеке.
- **Третья эпоха SFT хуже двух.** На обоих dev интервал разности целиком ниже нуля (таблица подбора в [extraction.md](extraction.md)). Loss на обучении упал до <!--n:sft/train_qwen3_1p7b_r16_e3.json:metrics.train_loss_last.value:.4f-->0.0076<!--/n--> (у двух эпох <!--n:sft/train_qwen3_1p7b_r16.json:metrics.train_loss_last.value:.4f-->0.0196<!--/n-->): похоже, модель точнее повторяет silver-метки вместе с их ошибками. Оговорка: в этом прогоне вместе с эпохами поменялся и silver (из него убраны посты, чей текст изменила чистка персональных данных), так что вклад двух правок по отдельности он не разводит.
- **Реранкер ухудшил MRR.** Кросс-энкодер bge-reranker-v2-m3 поверх первых 20 кандидатов на <!--n:models/matching.json:metrics.dev.rerank.queries.value:d-->100<!--/n--> резюме dev: nDCG@10 <!--n:models/matching.json:metrics.dev.rerank.diff.ndcg.value:+.3f-->+0.014<!--/n--> [<!--n:models/matching.json:metrics.dev.rerank.diff.ndcg.ci_low:+.3f-->-0.012<!--/n-->; <!--n:models/matching.json:metrics.dev.rerank.diff.ndcg.ci_high:+.3f-->+0.038<!--/n-->], MRR <!--n:models/matching.json:metrics.dev.rerank.diff.mrr.value:+.3f-->-0.133<!--/n--> [<!--n:models/matching.json:metrics.dev.rerank.diff.mrr.ci_low:+.3f-->-0.211<!--/n-->; <!--n:models/matching.json:metrics.dev.rerank.diff.mrr.ci_high:+.3f-->-0.052<!--/n-->], при этом <!--n:models/matching.json:metrics.dev.rerank.seconds_per_query_median.value:.0f-->25<!--/n--> с на резюме на CPU. В API его нет.
- **HTTPS как навык.** Извлечение принимало ссылки в посте за навык, а в Telegram почти каждый пост кончается ссылками. Сырой ответ модели не меняется, а витрины считают HTTP и HTTPS навыком, только если текст называет их вне ссылки (правило в `configs/skills.toml`, раздел `text_check`). На неделях прогноза с 2022 года правило убрало HTTP или HTTPS у <!--n:models/forecast.json:metrics.link_check.telegram.n:,d|ru-->19 897<!--/n--> из <!--n:models/forecast.json:metrics.link_check.telegram.denominator:,d|ru-->136 819<!--/n--> IT-постов Telegram, HTTPS остался у <!--n:models/forecast.json:metrics.link_check.telegram.named_n:d-->446<!--/n-->. Первый прогон прогноза исключал HTTPS руками, теперь исключений нет.
- **Space на Docker.** Демо задумывалось как Docker-контейнер с llama.cpp на бесплатном CPU Hugging Face, но Docker- и Gradio-Spaces на бесплатном тарифе теперь требуют платной подписки. Платные облака проект не использует, поэтому Space переделывается в статический, с моделью в браузере.

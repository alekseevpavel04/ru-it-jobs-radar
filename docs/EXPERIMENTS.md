# Журнал экспериментов

Гипотезы и фиксации выборок для извлечения полей из вакансий и для детектора подозрительных вакансий. Отрицательный результат записан так же, как положительный. Номера (E для экспериментов, S для выборок) сквозные, на них ссылаются конфиги. Каждое число на странице взято из файла в `results/` и пересчитывается `scripts/verify_numbers.py`. Где значение осталось только в консоли или в логе прогона, это сказано прямо, и числа нет.

Все сравнения на dev. Test ещё не считался.

## Правила

- Всё подбирается на dev: промпты учителей, состав silver-меток, рецепт обучения, правила детектора, пороги дедупа. Test считается один раз в конце командой с флагом `--final-test`, каждый запуск пишется в `results/test_runs.log`. Если test придётся пересчитать (например, из-за ошибки в коде метрики), здесь появится запись с причиной.
- Доля пишется со знаменателем. Интервалы 95%: парный бутстрап по записям, 2000 повторов, seed в `configs/eval.toml`. «A минус B» считается на одних и тех же записях.
- Правило остановки. Итерация рецепта (промпт учителя, правила, SFT) продолжается, пока прирост macro F1 по полям на dev не меньше 0,01. Два прироста подряд меньше 0,01 или четыре итерации на одной задаче: стоп, фиксируется лучшая версия.
- DPO нужен, если после остановки SFT доля валидного JSON на dev ниже 99% или какое-то поле у студента хуже учителя больше чем на 0,05 при остальных на уровне. Иначе DPO идёт только абляцией.
- Выборка замораживается хэшами списков id. Любая правка выборки это новая запись с причиной.
- Эталон: предразметка LLM в два независимых прохода одной модели по одной инструкции, третий проход по расхождениям, затем ручная проверка всех записей. Согласие двух проходов мерит согласованность предразметки, а не её правильность.

macro F1 это среднее F1 по восьми полям схемы (`[macro]` в `configs/eval.toml`). salary и cities на trudvsem и Хабре берутся из шапки полей источника и у эталона, и у правил, поэтому почти у всех систем там 1,000.

# Подозрительные вакансии и перевыкладки

Детектор: функции слабой разметки, классификатор и выборка для проверки. Код в `src/radar/models/suspicious.py`, `suspicious_lfs.py` (определения и функции), `suspicious_label.py` (объединение голосов и оценка по выборке). Числа в `results/models/suspicious.json`.

```
python -m radar.models.suspicious run       # голоса, слабые метки, классификатор, results
python -m radar.models.suspicious sample    # заморозить выборку для разметки (один раз)
```

## 1. Единица и данные

Единица это карточка вакансии у источника, пара `(семейство, source_id)`. Записи API trudvsem и ежедневных снимков с одним id это одна карточка, поля берутся из последней записи. Ключ не зависит от дедупа, поэтому замороженная выборка переживает его перезапуск.

Источники: trudvsem (снимки с 30.06, API с 08.10) и Хабр Карьера (с 08.10), все карточки, которые ведёт история (`staging.int_vacancy_records`). Telegram пока не входит: у постов нет полей работодателя, региона и зарплаты, и нет истории закрытий.

## 2. Что считается подозрительным

Карточка подозрительна, если она не честно предлагает ту работу, которую называет, на тех условиях, которые указаны. Четыре вида, каждый судится по самой карточке.

| Вид | Что это | Примеры |
|---|---|---|
| `course` | Карточка продаёт обучение | кандидат платит за курс, стажировку, материалы или тестирование; «вакансия» на деле набор на образовательную программу |
| `bait` | «Работа мечты» | высокий или неограниченный доход без опыта и без понятных обязанностей; пассивный доход, сетевой маркетинг, вложения кандидата; IT-заголовок над холодными звонками и планом продаж |
| `grey` | Серая занятость | постоянная работа без договора, зарплата в конверте или только наличными, просьба оформить банковскую карту или передать документы, предложение «нарисовать» опыт в резюме |
| `formal` | Заглушка вместо вакансии | текст из справочника должностей без единого слова о работе у этого работодателя, и при этом оплата не вяжется с обязанностями (разработчик ядра за пятую часть рынка); или карточка сама говорит, что размещена для формальности |

Не подозрительно само по себе:

- перевыкладка (раздел 3);
- низкая зарплата в бюджетном учреждении, на неполную ставку или у стажёра;
- кадровое агентство, которое называет заказчика или роль;
- работодатель-ИП: название вырезано при чистке персональных данных, это артефакт конвейера;
- рекрутер Хабра, который просит написать в Telegram;
- честно названная продажная работа («Менеджер по продажам IT-решений»);
- стажировка работодателя с обучением внутри и оплатой.

Цель публикации (например, формальная вакансия ради разрешения на найм) по карточке не устанавливается. Вид `formal` описывает признаки карточки, а не намерение работодателя.

## 3. Перевыкладки

Перевыкладка берётся из истории снимков (`staging.hist_reposts`): закрытая карточка и новая карточка с другим id у того же работодателя, в том же регионе, с тем же заголовком и текстом, появившаяся не позже 30 дней после закрытия. По каждой карточке детектор выдаёт флаг перевыкладки и длину цепочки id одной вакансии. У Хабра и среза API истории закрытий пока нет.

Перевыкладка не вид подозрительности: карточка портала истекает примерно через 30 дней (скачок закрытий в 7.3), и работодатели выкладывают её снова. Длинная цепочка (4 id и больше) включена как функция разметки, которая измеряется на выборке, но в слабую метку не входит: на всей совокупности она срабатывает в основном на массовый найм крупных работодателей.

## 4. Функции слабой разметки

Голос каждой функции: «подозрительно», «нормально» или воздержание. Функции видят поля источника, текст и историю, без LLM и без GPU. Шаблоны писались по срабатываниям на всей совокупности карточек до того, как выборка была заморожена, и никогда по самой выборке. Итераций правил было четыре, на этом остановка по правилу из `docs/EXPERIMENTS.md`.

| Функция | Голос | Вид | Правило |
|---|---|---|---|
| `course_pay` | подозрительно | course | кандидат платит за обучение (стоимость обучения, платный курс, внести взнос) |
| `training_then_job` | подозрительно | course | обучение с последующим или гарантированным трудоустройством |
| `income_bait` | подозрительно | bait | пассивный доход, сетевой маркетинг, MLM, арбитраж трафика, «без вложений», доход в день или в неделю |
| `unlimited_income` | подозрительно | bait | доход без потолка |
| `no_experience_high_pay` | подозрительно | bait | в тексте «без опыта», зарплата z от 2 |
| `sole_remote_no_experience` | подозрительно | bait | ИП, удалённо, в тексте «без опыта» |
| `salary_high` | подозрительно | bait | зарплата z от 3; измеряется, в метку не входит |
| `title_sales` | подозрительно | bait | технический IT-заголовок, в тексте холодные звонки или план продаж |
| `grey` | подозрительно | grey | без оформления, в конверте, только наличными, карта на себя, «нарисуем опыт»; отрицание рядом («никаких зарплат в конверте») гасит голос |
| `salary_low` | подозрительно | formal | технический IT-заголовок, зарплата z до минус 3, не стажёр и не неполная ставка |
| `mass_text` | подозрительно | formal | один текст у 5 и больше работодателей, 80% его карточек в одном регионе |
| `formal_note` | подозрительно | formal | карточка сама говорит о квоте или формальности |
| `repost_chain` | подозрительно | нет | 4 и больше id одной вакансии; измеряется, в метку не входит |
| `public_sector` | нормально | | государственное или муниципальное учреждение |
| `large_employer` | нормально | | у работодателя 50 и больше карточек за окно |
| `concrete_requirements` | нормально | | опыт от года (или заявленный грейд middle и выше) и 3 и больше навыков словаря |

Зарплата z: логарифм месячной зарплаты против медианы группы «роль × Москва, Петербург, регионы, удалённо», шкала IQR / 1,349 с нижней границей 0,2. Маленькая группа (меньше 30 зарплат) уходит в группу роли, затем во всю совокупность. Граница шкалы нужна, потому что у работодателя с сотнями одинаковых зарплат IQR региона почти ноль и любая другая сумма выглядела бы выбросом.

Шаблон из справочника профессий, который портал подставляет сотням работодателей в разных регионах, функцию `mass_text` не включает: нужна концентрация в одном регионе. ИП в подсчёт работодателей не входят, у них нет ИНН.

Покрытие, пересечения и конфликты каждой функции (n из знаменателя) лежат в `results/models/suspicious.json`, ключи `lf.<имя>.coverage`, `overlap`, `conflict`.

## 5. Как объединяются голоса

Слабая метка для обучения это голосование большинством функций, входящих в метку: «подозрительно» побеждает, если таких голосов больше, чем «нормально». Карточка без голосов считается нормальной, ничья в обучение не идёт. Нормальная по умолчанию опирается на редкость красных флагов в источниках: классификатор должен видеть обычные коммерческие карточки как отрицательные, а не только бюджетные учреждения и опытные роли. Сколько подозрительных пропускает это допущение, показывает страта `rest` выборки.

Для сравнения считается модель Дэвида-Скина (EM, как генеративная модель Snorkel): у каждой функции своя вероятность каждого ответа при каждом истинном классе, функции независимы при известном классе. Ей нужны пересечения голосов, чтобы отличить точность функции от покрытия. Здесь подозрительные функции почти не пересекаются, и EM сходится к самой крупной структуре голосов (какая функция «нормально» сработала), а не к подозрительности. Поэтому она остаётся кандидатом, которого оценивают на dev, а не обучающей меткой.

## 6. Классификатор

Логистическая регрессия на TF-IDF заголовка и текста (слова и пары слов) и 11 числовых признаках карточки: зарплата z, есть ли зарплата, «без опыта», ИП, число работодателей с тем же текстом, доля его главного региона, число карточек работодателя, длина цепочки перевыкладок, длина текста, число навыков, Хабр. Классы взвешены. Перекрёстная проверка в 5 фолдах, сгруппированных по тексту, чтобы шаблон не оказался по обе стороны.

Согласие классификатора со слабыми метками на отложенных фолдах показывает, что он их выучил, а не что он прав. Точность и полнота считаются только по размеченной выборке.

## 7. Выборка для проверки

300 карточек, 150 dev и 150 test, заморожены 11.10 по данным до 10.10, seed 20261008 из `configs/eval.toml`.

1. Все карточки делятся на две половины по хэшу текстовой группы с seed: одинаковый текст не попадает в обе.
2. В каждой половине страты: `lf:<имя>` по самой редкой подозрительной функции, которая сработала (так функции, сработавшие на несколько карточек, тоже попадают в выборку); `model_only`, классификатор отметил, а ни одна функция нет; `rest`, всё остальное.
3. Распределение на половину: 70 карточек поровну на страты функций (маленькая страта берётся целиком, остаток переходит дальше), до 20 на `model_only`, остальное на `rest`.
4. Внутри страты простая случайная выборка без возвращения. У каждой карточки вес N_h / n_h её страты; доли и полнота считаются отношением взвешенных сумм, интервал бутстрапом внутри страт (2000 повторов, 95%).

Файлы в `data/suspicious/` (вне git):

| Файл | Что |
|---|---|
| `sample_dev_inputs.jsonl`, `sample_test_inputs.jsonl` | вход разметчика, карточки в случайном порядке |
| `sample_design.json` | соответствие item_id карточке, страта, размеры страт, хэши |
| `labels_dev.jsonl`, `labels_test.jsonl` | итоговые метки после сведения двух проходов (кладёт оркестратор) |

Хэши списков карточек и входных файлов попадают в `results/models/suspicious.json`, раздел `sample`. `sample` не перезаписывает выборку, у которой есть метки. Dev оценивается при каждом `run`, test только с `--final-test` (запуск пишется в `results/test_runs.log`).

## 8. Инструкция разметчику

Предразметка LLM в два независимых прохода по одной инструкции, расхождения сводятся отдельно, затем ручная проверка. Разметка другого прохода не открывается.

### Что на входе

Одна карточка в строке: `item_id`, источник, ссылка, заголовок, работодатель, регион или города, зарплата (текстом и числами), требуемый опыт, заявленный грейд (Хабр), график, занятость и текст (до 5 000 символов, `text_truncated` говорит, обрезан ли). Голосов функций, оценок модели и истории во входе нет намеренно: решение принимается по карточке, как её видит соискатель.

### Что на выходе

Одна строка на карточку в файл своего прохода (имя задаёт оркестратор):

```json
{"item_id": "d001", "label": "suspicious", "categories": ["course"], "reason": "кандидат оплачивает курс до трудоустройства"}
```

- `label`: `suspicious`, `ok` или `unsure`. `unsure` ставится редко и только с причиной, чего не хватает.
- `categories`: для `suspicious` один или несколько видов из `course`, `bait`, `grey`, `formal`; для остальных `[]`.
- `reason`: одна короткая фраза, какой признак решил.

### Как решать

1. Прочитай заголовок, затем обязанности и условия. Вопрос один: предлагает ли карточка эту работу на этих условиях.
2. `suspicious` ставится по признаку из таблицы раздела 2, который виден в карточке. Подозрение без признака в тексте это `ok`.
3. Для `formal` нужны оба условия: текст без единой подробности о работе у этого работодателя (только перечень из справочника должностей) и оплата, которая не вяжется с обязанностями для этого региона. Одного шаблонного текста мало: бюджетные учреждения часто так пишут и правда нанимают.
4. Название работодателя, в том числе иностранное по звучанию, признаком не служит. ИП признаком не служит.
5. Перевыкладка, срок публикации и число похожих карточек во входе не видны и на решение не влияют.

### Спорные случаи

| Случай | Решение |
|---|---|
| «Бесплатное обучение», «оплата курсов за счёт компании» | `ok`, это льгота |
| Стажировка с обучением и оплатой, трудоустройство после успешного окончания | `ok` |
| Обучение с «гарантированным трудоустройством», оплата обучения кандидатом или ни слова об оплате работы | `suspicious`, `course` |
| Продажи под честным заголовком, доход «без потолка» из оклада и процента | `ok` |
| «Аналитик данных», а в обязанностях холодные звонки и план продаж | `suspicious`, `bait` |
| Удалённый «модератор» или «оператор чата», опыт не нужен, доход выше обычного для такой работы, о работодателе ни слова | `suspicious`, `bait` |
| «Официальное оформление, никаких серых схем» | `ok` |
| «Можем рассмотреть и без оформления» при постоянной работе | `suspicious`, `grey` |
| Разработчик ядра или техлид с зарплатой на уровне минимальной в Москве, текст из справочника | `suspicious`, `formal` |
| Системный администратор школы на 0,25 ставки за 15 000 | `ok` |
| Текст на английском | решается теми же правилами |
| Подробный текст, но о продукте другой компании, а не о работе у названного работодателя (один текст у разных работодателей), оплата в разы ниже рынка | `suspicious`, `formal`: условие «без подробностей о работе у этого работодателя» выполнено |
| Справочный текст с одной общей фразой («готовность к командировкам», «продвижение на маркетплейсах») | фраза не подробность о работе, решает оплата |
| Оплата для `formal`: ориентир «втрое и больше ниже обычного для роли и опыта в этом регионе»; половина рынка в регионе не признак | порог задан после первых двух проходов (сведение 11.10) |
| Подробный текст и сумма, похожая на ошибку в поле (до 30 000 у руководителя, 999 999) | `ok`: ошибка в поле не обман |
| Стажировка: обучение без оплаты кандидатом, оклад после обучения назван | `ok` |
| «Менеджер» с продажами по телефону, обязанности названы | `ok`, как продажи под честным заголовком |
| Удалённый оператор или модератор без опыта: `bait`, если доход заметно выше 50 000 и о работодателе ни слова | 35 000-50 000 обычный уровень такой работы |

### Чего не делать

- Не искать внешние источники и не открывать ссылку: решение только по входу.
- Не смотреть разметку другого прохода.
- Не ставить `suspicious` за бедный текст: короткая карточка без подробностей это не обман.

## 9. Ограничения

- Метки функций слабые. Классификатор учится на них и наследует их перекосы; насколько, покажет dev.
- Красные флаги в тексте на портале и Хабре редки: обе площадки модерируются. Подозрительных карточек в совокупности мало, поэтому интервал полноты по страте `rest` широкий.
- Выборка и её веса относятся к совокупности на дату заморозки. Данные растут (бэкфилл снимков), предсказания на размеченных карточках пересчитываются при каждом `run`, веса нет.
- В календаре снимков есть пропуск (на 11.10 с 20.09 по 08.10, бэкфилл идёт). Закрытия и новые карточки внутри пропуска датируются его концом, поэтому для перевыкладок на этой границе окно в 14 и 30 дней мерит не настоящий зазор.

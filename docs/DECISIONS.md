# Решения

Принятые решения проекта с датой. На номера ссылаются документация («решение 10») и комментарии в коде (`DECISIONS 10`). Если решение меняется, старая запись остаётся, а ниже дописывается новая с датой и причиной.

### 1. Источники

**2026-10-08.** Вакансии берутся из открытых данных портала «Работа в России» (trudvsem: API и ежедневные XML-снимки набора), Хабр Карьеры и публичных Telegram-каналов с вакансиями (веб-превью t.me/s/). SuperJob подключается, если будет ключ API. hh.ru не используется: открытого API для такой задачи у него нет.

**2026-10-12.** Ключ API SuperJob получен, коллектор SuperJob подключён (`docs/sources.md`, раздел SuperJob). trudvsem забирается только через документированный API и файлы набора открытых данных, с паузой 2 с между запросами и ссылкой на trudvsem.ru.

Следствие: срез рынка смещён в сторону вакансий, которые попадают в эти источники. Это описано в методике и учитывается при чтении цифр.

### 2. Что публикуется

**2026-10-08.** Исходные тексты вакансий публикуются только из открытых данных trudvsem, со ссылкой на источник. По Хабр Карьере и Telegram публикуются только агрегаты и извлечённые поля, без исходного текста. Тексты этих источников хранятся только в локальном сыром слое.

**2026-10-12.** Уточнение по итогам аудита источников. Записи trudvsem с пометкой «Вакансия интернет ресурса» перепубликованы с коммерческих сайтов: их тексты не публикуются, только поля. Хабр Карьера на сайте и в датасете HF представлена только агрегатами, без построчных извлечённых полей: построчные поля тоже производное от их базы.

### 3. Персональные данные

**2026-10-08.** Персональные данные (ФИО контактов, телефоны, почты, ники) вычищаются до записи в сырой слой (152-ФЗ).

**2026-10-12.** Уточнение: хэши контактов тоже не хранятся, потому что хэш контакта остаётся персональными данными; перевыкладки ловятся без контактов. У работодателей-ИП не хранятся имя, ИНН, ОГРНИП и адрес.

### 4. Полнота важнее скорости

**2026-10-08.** Объём проекта не урезается молча. Если модуль не получается, причина с цифрами записывается сюда, а вместо него делается замена сопоставимого веса.

### 5. Бесплатно и доступно из России

**2026-10-08.** Платные API и облака не используются. Публичная часть живёт на GitHub Pages и Hugging Face (Space на бесплатном CPU) и должна открываться из России без VPN.

### 6. Методика эталона

**2026-10-08.** Эталон для оценки извлечения: 400 и больше вакансий, предразметка LLM в два независимых прохода по одной инструкции (`docs/annotation_guide.md`), третий проход по расхождениям, затем ручная проверка. Первой идёт выборочная проверка 50 примеров через HTML-страницу, её размер и результат попадают в README.

### 7. Публикация и автообновление

**2026-10-08.** Сайт, датасет и модели публикуются после проверки конкретного результата. После этого ежедневное обновление данных и пересборка сайта идут автоматически.

**2026-10-08.** Уточнено решением 12: автообновление действует до финальной версии проекта. После неё сбор продолжается по cron, а сайт автоматически не пересобирается.

### 8. Dev и test

**2026-10-08.** Гиперпараметры, промпты и рецепты обучения подбираются только на dev. Test считается один раз в конце, каждый запуск записывается в `results/test_runs.log`.

### 9. Модели

**2026-10-08.** Учителя для разметки обучающего корпуса: Qwen3-8B и YandexGPT-5-Lite-8B (локальные GGUF через llama.cpp). Ученики: Qwen3 1.7B и 4B, QLoRA SFT, затем DPO, если SFT упрётся. Бюджет: обучение до 4B в QLoRA на одной карте 8 ГБ, инференс до 4B в 4 битах.

**2026-10-13.** Правило из `docs/EXPERIMENTS.md` (поле студента ниже учителя больше чем на 0.05) сработало по точке: формат работы в Telegram -0.067 [-0.163; 0.023] на 54 постах, интервал включает ноль. DPO на 716 парах не поместился в карту 8 ГБ ни в одной из четырёх проб (пик памяти от 7 152 до 11 718 МиБ при пределе 6 586), потому что DPO грузит модель без оптимизаций, на которых шло SFT. Финальный тест считается без DPO, публикуется студент только после SFT; код DPO и пары остаются в репозитории.

### 10. Telegram: агрегаты и корпус извлечения

**2026-10-08.** Посты публичных каналов собираются через веб-превью t.me/s/ и хранятся только в локальном сыром слое. На сайт идут недельные агрегаты: роли и навыки считаются словарём и правилами. Эталон и обучающий корпус пока собраны из trudvsem и Хабр Карьеры; если в них окажется мало ML-, DS- и data-вакансий (порядка 300 в обучающем пуле), Telegram добавляется в обучающий корпус.

**2026-10-11.** Telegram входит в обучающий корпус извлечения: в trudvsem и Хабр Карьере ML-, DS- и data-вакансий мало (154 из 16 897 в обучающем пуле), а в постах Telegram их тысячи. Для оценки на свободном тексте собран отдельный эталон из постов Telegram (test 140, dev 60) той же методикой. Тексты постов по-прежнему не публикуются (решение 2), на сайте только агрегаты.

**2026-10-12.** Канал remoteit, где большинство постов на английском (зарубежная удалёнка), остаётся в списке, но в агрегатах и корпусе извлечения считаются только его русские посты (`docs/sources.md`, раздел «Только русские посты remoteit»).

### 11. Ежедневный сбор на отдельном сервере

**2026-10-08.** Коллекторы каждый день запускаются по cron на отдельном сервере (`docs/vps.md`) и пишут Parquet. Рабочая машина забирает партиции и загружает их в стек. Сбор не зависит от того, включена ли рабочая машина.

**2026-10-08.** Уточнение: сервер оказался домашним, с тем же внешним адресом, что у рабочей машины. Внешний VPS остаётся запасным вариантом для Хабр Карьеры, если начнутся блокировки.

### 12. Точка проекта

**2026-10-08.** Проект не ждёт месяц собственного сбора. История для сроков жизни вакансий, рядов, прогноза и дрейфа берётся из 100 ежедневных снимков trudvsem и из истории Telegram-каналов. Проверка конвейера: прогон Airflow за 7 прошлых дат и два ночных запуска на сервере. Точка проекта: финальная версия со срезом данных на дату. После неё сбор продолжается по cron, а сайт автоматически не обновляется.
